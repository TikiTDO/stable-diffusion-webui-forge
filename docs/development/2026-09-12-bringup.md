# The Diffusatory bring-up journal — 2026-09-12

This is a working engineering record for the first modernization pass over the
Forge fork. It records what was actually exercised, the compatibility seams we
found, and which inherited capabilities still need proof. It is deliberately
not the final product architecture.

## Intent

The first milestone is intentionally boring: preserve the useful inherited
capabilities on a current runtime before replacing the inherited UI and
extension architecture. A rendered form is not accepted merely because it
looks complete; its event path must reach inference and return a usable result.

Once that baseline exists, the product can make characters, scenes, poses,
regions, layers, projects, and image sets native concepts rather than forcing
them through extension glue.

## Operator product boundary

This fork is not trying to remain a universal A1111 interface. Its supported
model families are **SDXL and Flux**. SD 1.x/2.x support may be removed all the
way through the stack wherever SDXL or Flux does not share the machinery.

The workflows to preserve and improve are:

- txt2img, extensive img2img, and inpaint;
- prompts, embeddings, checkpoints, VAEs/text encoders, and LoRAs;
- frequent ControlNet use, especially IP-Adapter, depth, lineart, and OpenPose;
- Regional Prompter behavior as native composition;
- Dynamic Prompts behavior for occasional brainstorming and story progressions.

Most inherited tabs, model families, and extension surfaces are not product
requirements. Removing them still needs a dependency trace: `sd` is also a
generic name in code paths used by SDXL.

## Measured repair sequence

### Environment bootstrap

1. Current Setuptools no longer supplies `pkg_resources` by default. Built-in
   installers and runtime version checks were moved to `importlib.metadata` and
   `packaging.version`.
2. The old CLIP repository revision depended on the removed `pkg_resources`
   surface. The launcher now uses the current OpenAI CLIP revision.
3. Direct runtime imports that were missing from the declared environment,
   including `joblib` and `sentencepiece`, are explicit requirements.
4. The PyPI xFormers wheel installed successfully but did not contain usable
   CUDA kernels for this stack. The matching PyTorch CUDA index wheel did.
5. InsightFace 2.0 provides a portable Python 3.13 wheel and retains the
   `FaceAnalysis` and `face_align.norm_crop` surfaces used by Forge. The old
   Windows-only 0.7.3 bootstrap is no longer the default.

### Gradio 6 form compatibility

The first page render looked plausible while the form was effectively dead.
The following were separate failures:

1. Forge's injected JavaScript and CSS used the removed `/file=` route. Every
   core custom asset returned HTTP 404, leaving `submit`, `gradioApp`, and
   `requestProgress` undefined. Static assets now use
   `/gradio_api/file=`.
2. Hidden ControlNet sliders intentionally use `-1` as an unresolved/default
   sentinel, while their initial visible range began at 64. Gradio 6 validates
   hidden component values. Source defaults now admit the sentinel, and the UI
   configuration loader migrates saved out-of-range slider values without
   discarding the user's value.
3. Old XYZ-grid multiselect values were persisted as the empty string. Gradio 6
   requires a list for multiselect dropdowns. The configuration loader converts
   the legacy empty value to `[]`.
4. Gradio added an argument to the internal block configuration method. Forge's
   wrapper now forwards arbitrary positional and keyword arguments.
5. Forge's temporary-file override still emitted `/file=` for generated images.
   The inference completed and the PNG was valid, but the gallery requested a
   URL that returned HTTP 404. The override now follows Gradio's API prefix and
   path encoding while retaining Forge's no-copy cache behavior.

These are persistence-boundary migrations, not reasons to delete a user's UI
configuration. Any future form rewrite needs the same rule: stored state has a
schema even when it lives in a JSON file without an explicit schema document.

### Browser lifecycle and gallery

The initial document reached the DOM quickly but kept replaying known server
state through Gradio load callbacks. A page with 2,395 components did not
become reliably writable until roughly 67 seconds after navigation. The repair
removed post-mount rewrites of 388 settings values, 20 generation controls,
and nine Forge Space cards; those values now enter the initial component
configuration. The current document has 770 dependencies, 28 load handlers,
and no queued load handler.

On a clean browser document the prompt became reliably writable in 11.1
seconds. Settings mounted in 590 ms, a settings-page switch completed in 62 ms,
and Img2img mounted in 808 ms. A cold four-step 512x512 UI generation then
reached a visibly loaded gallery image in 6.96 seconds. An independent
eight-step 896x1152 run also completed through the visible UI in 3.3 seconds
after the model was warm.

Gradio 6 changed the gallery DOM and lazy image behavior. Forge's old
click-to-lightbox selector therefore matched no result images, while Gradio's
native Fullscreen action enlarged the complete gallery component and page
layout. Current result images are loaded eagerly when Chromium leaves a newly
inserted lazy image pending. Direct image clicks and the toolbar Fullscreen
button now both use Forge's viewport-bounded lightbox rather than Gradio's
component fullscreen mode.

### Transformers 5 model compatibility

Transformers 5 moved `no_init_weights` from `modeling_utils` to
`transformers.initialization`, and flattened `CLIPTextModel` so it no longer
contains a `text_model` child. Forge's loaders now use a version-neutral
initialization helper. The integrated CLIP wrapper restores Forge's stable
`transformer.text_model.*` layout only for the flattened model, keeping both
checkpoint keys and the prompt-processing path stable.

## Current form anatomy

The inherited page mixes several different jobs in one long document:

1. **Runtime selection** — model family, checkpoint, VAE/text encoder, low-bit
   policy, and GPU allocation.
2. **Prompt authoring** — positive/negative text, token counters, style actions,
   and extra-network insertion.
3. **Generation recipe** — sampler, schedule, steps, size, seed, batch, hires,
   refiner, and integrated script accordions.
4. **Conditioning inputs** — three repeated ControlNet units with image canvas,
   preprocessor, model, ranges, and resize/control policies.
5. **Result workspace** — gallery/canvas, metadata, save/send/open actions, and
   progress/interrupt state.
6. **Asset browsers** — textual inversion, checkpoints, and LoRA cards.

The browser currently receives more than two thousand Gradio components. Many
hidden components are not merely visual; they are DOM bridges for legacy
JavaScript callbacks. Gradio 6's decision not to mount `visible=False`
components exposed that hidden coupling. Replacing the forms should therefore
start from events and state ownership, not from rearranging visible controls.

## Rewrite observations

### Preserve

- model detection and Forge's memory-management backend
- explicit generation recipes and reproducible infotext
- checkpoint, VAE, LoRA, preprocessor, ControlNet, and IP-Adapter capability
- progress, interrupt, preview, and output metadata
- the useful algorithms inside the copied extensions

### Replace or absorb

- extension registration as the primary product composition mechanism
- implicit DOM bridges hidden inside form components
- monkeypatches that copy an old dependency implementation indefinitely
- duplicated model/asset registries
- long accordions that make advanced capabilities discoverable only by memory
- bare filesystem state where projects and reusable creative objects need an
  explicit schema

### Candidate native product concepts

- **Project** — owns assets, recipes, outputs, history, and provenance.
- **Character** — reusable identity references, LoRAs, embeddings, prompt
  fragments, and constraints.
- **Scene** — composition, camera, environment, and regional prompt layout.
- **Pose / structure** — sketches, depth, edges, joints, masks, and ControlNet
  inputs as editable relations rather than unrelated upload boxes.
- **Region / layer** — a first-class target for prompts, masks, adapters, and
  compositing. Regional prompting should enter here as native core behavior.
- **Image set** — related candidates, comparisons, selections, and derived
  generations rather than a flat output folder.
- **Recipe** — the complete reproducible inference plan, separated from the
  transient rendering of its form.
